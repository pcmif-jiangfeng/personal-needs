# Phase 1 决策与约定

- 用户要求分阶段，当前仅完成 Phase 1，不将状态页冒充完整 MVP。
- Python 标准库 HTTP + SQLite + 原生 HTML，避免包安装和构建链。后续可替换前端，数据库保持独立。
- `records` 保存观察事件；`themes` 保存需求主题；`tags` 支持场景、问题类型及自定义分类；`record_tags` 支持多对多。`related_need` 为可空主题外键。
- 同名标签可存在不同分类（例如“信息整理”），后续界面需显示分类。`scene` 为单一主场景，场景标签为补充；周复盘主场景统计以 `scene` 为准，避免重复计数。
- `context`、`problem` 非空，感受为 JSON 数组；Phase 2 表单提供感受多选。五项评分均可空，遵循文档最后“低记录阻力”原则。
- 原始 context/problem/feeling 在首次写入时保存到 original_*，数据库触发器阻止后续覆盖；编辑修改当前字段。服务层负责首次同步写入。
- 时间保存为 UTC ISO 8601，后续界面用本地时区展示；周复盘按本地周一零点到下周一零点过滤。occurred_at 是发生时间，created_at 是录入时间。
- 更新时由后续服务层显式刷新 updated_at；当前无修改接口。
- 删除主题仅解除归属，保留记录；删除记录级联删除标签关联，不删除标签和其他记录。
- 不存储易过期的 opportunity_score 与主题统计；后续按记录和当前配置计算。
- 归一化约定：(加权均分 - 1) / 4 × 100，使全 1 分为 0，全 5 分为 100。五项未填全时显示“待补评分”，不把缺失项当成 0 或伪造评分。Phase 4 实现计算与配置校验。
- schema_migrations 已记录 v1；以后结构变更须添加版本化迁移，不仅修改 CREATE TABLE IF NOT EXISTS。当前初始化可重复执行且不覆盖数据。
- 真正的聚类、AI、账户、同步均不在 MVP；项目分析和 Prompt 按后续阶段实现。
- 数据库目录被 gitignore 排除。当前备份应停止应用后复制整个 data 目录；业务导出在 Phase 3 实现。
